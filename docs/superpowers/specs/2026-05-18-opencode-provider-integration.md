# OpenCode Provider Integration Design

## Overview

Extend the AI Harness CLI to support OpenCode as an agent provider, enabling automatic setup of `.opencode/` directory structure and `opencode.json` configuration based on `.ai.toml` provider declarations.

## Current State Analysis

### Existing Architecture

The CLI uses a template-based scaffolding system:
- **Templates location**: `templates/<component>/<version>/`
- **Project installation**: Copies to `.ai/harness/<component>/`
- **Configuration**: `.ai.toml` tracks installed components
- **Commands**: `ah init`, `ah add <component>`, `ah validate`

### Configuration Schema (Current)

```toml
[project]
name = "my-project"
topology = "typescript-lib"

[harness]
base = ["base@1.0.0"]
runtime = ["typescript@1.0.0"]
```

## Design Goals

1. **Provider-driven setup**: Read `[agent-providers]` from `.ai.toml` to determine which AI tool configurations to generate
2. **Multi-provider ready**: Architecture supports future providers (cursor, copilot, etc.)
3. **Granular control**: Allow selecting specific components (agents, skills, commands) or copying all
4. **Automatic configuration**: Generate both directory structure AND tool-specific config files

## Proposed Configuration Schema

### Extended .ai.toml Format

```toml
[project]
name = "my-project"
topology = "typescript-lib"

[harness]
base = ["base@1.0.0"]
runtime = ["typescript@1.0.0"]

[agent-providers]
providers = ["opencode"]

# Optional: Fine-grained control per provider
[agent-providers.opencode]
components = ["agents", "skills", "commands"]  # "all" for everything
targets = [".opencode/", "opencode.json"]      # Where to install
```

### Provider Syntax Options

**Simple form** (recommended default):
```toml
[agent-providers]
providers = ["opencode"]
# Installs everything: agents/, skills/, commands/ + opencode.json
```

**Selective form**:
```toml
[agent-providers]
providers = ["opencode:agents", "opencode:skills"]
# Only installs agents and skills directories
```

**Explicit form** (for complex cases):
```toml
[agent-providers]
providers = ["opencode"]

[agent-providers.opencode]
components = ["agents", "commands"]
skip_json = false  # Set true to skip opencode.json generation
```

## Provider Manifest Format

Each provider template includes a `manifest.toml` defining capabilities:

```toml
[provider]
name = "opencode"
version = "1.0.0"
description = "OpenCode agent provider with agents, skills, and commands"

[components]
agents = { path = "agents/", description = "Agent definitions" }
skills = { path = "skills/", description = "Reusable skills" }
commands = { path = "commands/", description = "Custom slash commands" }

[outputs]
directories = [".opencode/"]           # Directories to create
config_files = ["opencode.json"]       # Configuration files to generate

[configuration]
template = "opencode.json"             # Template for config generation
variables = ["project_name", "topology"]  # Variables to substitute
```

## CLI Integration

### Modified Commands

#### `ah init` Enhancement

```typescript
// New flow:
1. Create .ai/ directory (existing)
2. Create .ai.toml (existing)
3. Add base component (existing)
4. NEW: Check for [agent-providers] in template
5. NEW: If providers specified, run provider setup
```

#### `ah add` Enhancement

```bash
# Existing: Add harness component
ah add typescript

# NEW: Add with provider auto-setup
ah add base --provider opencode

# NEW: Add provider explicitly
ah add opencode

# NEW: Add specific provider component
ah add opencode:agents
```

#### New Command: `ah provider`

```bash
# List available providers
ah provider list

# Setup provider in current project
ah provider setup opencode

# Update provider files
ah provider update opencode

# Remove provider
ah provider remove opencode
```

### ProviderStore (New Class)

```typescript
// src/scaffold/provider-store.ts
export class ProviderStore {
  // Load provider manifest
  loadProvider(name: string, version?: string): ProviderManifest;
  
  // Check if provider exists
  hasProvider(name: string): boolean;
  
  // Get available providers
  getAvailableProviders(): string[];
  
  // Parse provider string (e.g., "opencode:agents,skills")
  parseProviderSpec(spec: string): { name: string; components: string[] };
}
```

### ProviderScaffolder (New Class)

```typescript
// src/scaffold/provider-scaffolder.ts
export class ProviderScaffolder {
  // Setup provider based on .ai.toml configuration
  async setupProvider(
    projectPath: string,
    providerSpec: string,
    options?: ProviderOptions
  ): Promise<void>;
  
  // Generate opencode.json with substitutions
  private generateConfig(
    templatePath: string,
    variables: Record<string, string>
  ): string;
  
  // Copy selected components
  private copyComponents(
    sourcePath: string,
    targetPath: string,
    components: string[]
  ): void;
}
```

## Configuration Generation

### opencode.json Template

```json
{
  "agents": {
    "code-agent": {
      "path": ".opencode/agents/code-agent.md"
    },
    "review-agent": {
      "path": ".opencode/agents/review-agent.md"
    }
  },
  "skills": {
    "brainstorming": {
      "path": ".opencode/skills/brainstorming.md"
    }
  },
  "commands": {
    "explain": {
      "path": ".opencode/commands/explain.md"
    }
  },
  "instructions": "{{project_name}} is a {{topology}} project."
}
```

Variable substitution from `.ai.toml`:
- `{{project_name}}` → `project.name`
- `{{topology}}` → `project.topology`

## Implementation Phases

### Phase 1: Foundation

1. Create `templates/opencode/1.0.0/` structure with sample files
2. Add `manifest.toml` to define provider capabilities
3. Implement `ProviderStore` class for loading providers
4. Add provider types to `src/types/`

### Phase 2: Scaffolding

1. Implement `ProviderScaffolder` class
2. Add component filtering logic (parse "opencode:agents,skills")
3. Implement config file generation with template substitution
4. Update `ProjectScaffolder` to call provider setup

### Phase 3: CLI Integration

1. Update `init.ts` command to read `[agent-providers]`
2. Update `add.ts` command to support `ah add opencode`
3. Create new `provider.ts` command with subcommands (list, setup, update, remove)
4. Update `.ai.toml` parsing to include provider section

### Phase 4: Validation & UX

1. Add validation in `validate.ts` for provider configurations
2. Add `ah provider list` to show available providers
3. Add progress indicators for provider setup
4. Write tests for provider scaffolding

## Usage Examples

### Initialize with OpenCode Provider

```bash
# Create new project with opencode support
mkdir my-project && cd my-project
ah init --template typescript --provider opencode

# Creates:
# - .ai.toml with [agent-providers] section
# - .ai/harness/base/
# - .opencode/agents/, .opencode/skills/, .opencode/commands/
# - opencode.json
```

### Add Provider to Existing Project

```bash
# Edit .ai.toml to add:
# [agent-providers]
# providers = ["opencode"]

# Then run:
ah provider setup opencode
```

### Selective Component Installation

```bash
# Only install agents and skills
ah add opencode:agents,skills

# Or via .ai.toml:
# [agent-providers]
# providers = ["opencode:agents", "opencode:skills"]
```

### Update Provider Files

```bash
# Refresh opencode files to latest version
ah provider update opencode
```

## Error Handling

### Provider Not Found
```
Error: Provider "cursor" not found
Available providers: opencode
Run `ah provider list` to see all providers
```

### Invalid Component Spec
```
Error: Invalid component "opencode:invalid"
Available components for opencode: agents, skills, commands
```

### Config Already Exists
```
Warning: .opencode/ directory already exists
Use --force to overwrite or `ah provider update` to refresh
```

## Testing Strategy

1. **Unit tests**: ProviderStore parsing, template substitution
2. **Integration tests**: Full `ah init --provider opencode` flow
3. **Validation tests**: Verify generated opencode.json format
4. **Edge cases**: Missing manifests, invalid provider specs

## Future Considerations

- Support for multiple providers simultaneously
- Provider-specific CLI flags (e.g., `--opencode-agents-only`)
- Automatic provider detection based on project files
- Provider marketplace/registry for third-party providers
- Version pinning for provider components

## Migration Path

Existing projects can add opencode support by:

1. Adding `[agent-providers]` section to `.ai.toml`
2. Running `ah provider setup opencode`

No changes needed to existing harness components.
